## Streaming Implementation

### Architecture

```
HTTPS GET (streaming) → zstd -dc (pipe) → Incremental PGN parser → Game replay → Position validation → Phase bucketing
```

### Key components

1. **Node `https` module** — streams the `.pgn.zst` file from Lichess CDN (with redirect following)
2. **`zstd -dc` child process** — decompresses Zstandard-compressed data on-the-fly via stdin/stdout pipe
3. **`StreamingPgnParser`** — buffers decompressed chunks, detects `\n[Event "` boundaries, emits complete game blocks
4. **Stop condition** — after each valid position is accepted, checks if all phase targets are met; if so, destroys the HTTP response and kills the zstd process

### Required tooling

`zstd` CLI must be installed:

| Platform | Command |
|----------|---------|
| Windows (winget) | `winget install Meta.Zstandard` |
| Windows (choco) | `choco install zstandard` |
| Linux | `sudo apt install zstd` |
| macOS | `brew install zstd` |

## What the Generator Supports

### Accepted source formats

| Mode | Format | Description |
|------|--------|-------------|
| `--source` | `.pgn` | Local multi-game PGN with full move text |
| `--source` | `.json` | JSON array of game objects with a `moves` field |
| `--source` | `.ndjson` / `.jsonl` | One JSON game per line |
| `--source-url` | `.pgn.zst` | Lichess PGN dump, streamed + decompressed on-the-fly |

### Rejected source types

- FEN-only datasets (no legal move history)
- Puzzle FEN + solution with no previous move
- Manually guessed previous positions
- Positions generated by reversing moves from FEN
- Random legal self-play games

### CLI usage

```
# Local file
node scripts/generate-training-corpus.mjs --source <path> [options]

# Streaming URL (Lichess dump)
node scripts/generate-training-corpus.mjs --source-url <url> [options]

Options:
  --out <dir>         Output directory (default: public/generated-training)
  --opening <n>       Target opening positions (default: 10000)
  --middlegame <n>    Target middlegame positions (default: 10000)
  --endgame <n>       Target endgame positions (default: 10000)
  --puzzles <n>       Target puzzle positions (default: 0)
  --seed <n>          Random seed (default: 42)
  --strict            Exit non-zero on shortfalls
  --dry-run           Validate and report without writing files
```

### Pipeline steps

1. Stream/load source (PGN, JSON, NDJSON, or `.pgn.zst` URL)
2. Replay each game with chess.js, capturing `previousFen` before every move
3. Validate every position via inlined `validateSetupPrelude` (mirrors `lib/training/setup-prelude.ts`)
4. Deduplicate by normalized FEN key (board + side + castling + en passant)
5. Exclude terminal positions (checkmate, stalemate, draw, no legal moves)
6. Classify by phase (opening ply ≤20, middlegame ply 21-70, endgame based on material)
7. Stop streaming when all targets are met
8. Write output JSON files

### Phase heuristics

- **Opening:** ply between 1 and 20 inclusive
- **Middlegame:** ply between 21 and 70, not classified as endgame
- **Endgame:** ≤10 pieces, OR no queens + low non-pawn material (≤6 pieces), OR ply >70 with ≤14 pieces
